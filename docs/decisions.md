# NetWatch 2.0 decisions log

Decisions taken while completing 2.0 where the brief was ambiguous or where the code already went another way.
Each entry: what was decided, and why.

| # | Date | Topic | Decision | Why |
|---|---|---|---|---|
| 1 | 2026-11-21 | Starting point | 2.0 work starts from 1.4.0 (Phases 4 and 5 were committed after the 68 % status report), not from 1.2.0. Each work package fills the gaps between 1.4.0 and the 2.0 brief instead of re-implementing what exists. | Avoids duplicate code and keeps 1.3/1.4 data compatible. |
| 2 | 2026-11-21 | Configuration precedence | defaults → data-folder `appsettings.json` → `NETWATCH_*` environment variables (`NETWATCH_Https__Port`) → command line (`--Https:Port=8444`). | The settings file used to be added last, so it silently overrode the command line. |
| 3 | 2026-11-21 | Start-up test | `--self-test` starts the full host (databases, seeding, hosted services, Kestrel), runs `SelfTest:Seconds` (default 5), stops, exits 0. The unit test runs it on an empty temp folder with `--simulate --Https:Port=0`, and two tests call `HasPendingModelChanges()` on both EF contexts. | Catches a missing migration (the 1.2.0 working-tree crash) and any start-up exception in CI. The same switch can be used after installation. |
| 4 | 2026-11-21 | Version | `2.0.0-dev` during development. Inno Setup's `VersionInfoVersion` must be numeric, so `build.ps1` passes `/DNumericVersion` (the version without its pre-release suffix). | Inno Setup rejects `2.0.0-dev` there. |
| 5 | 2026-11-21 | WEF per DC | `UseForwardedEvents` = every DC uses Windows Event Forwarding; otherwise `ForwardedDcs` (name, short name or IP) lists the DCs that use it and the rest are read remotely. Stored in the `dc` settings, so no schema change. | Brief asks for a per-DC choice; a settings list avoids a migration and works for DCs added later by name. |
| 6 | 2026-11-21 | 4624 noise | `SuccessfulLogonIgnoreSources` (IP, IPv4/IPv6 CIDR, or workstation name) drops successful logons from known application servers; it never applies to failures. Default empty. Logon type 3 stays excluded by default via `SuccessfulLogonTypes` [2, 7, 10, 11]. | "Ignore logon type 3 from known servers" without hiding failed logons. |
| 7 | 2026-11-21 | Security-log back-off | After consecutive failed Security-log reads the DC is retried after 1, 2, 4, 8, 16, then every 30 min. The bookmark only advances on success, so nothing is lost. Directory Service/DFSR logs and replication checks are not delayed. | A DC with a permission problem should not be hammered every poll, and one warning (1st and 6th failure) is enough in the log. |
| 8 | 2026-11-21 | DC samples | Parser tests use one full event per ID in `tests/NetWatch.Tests/Samples/Dc/<id>.xml`, written in the exact `EventRecord.ToXml()` schema with every EventData field of that event. They must be replaced by exports from the real DCs during the pilot (`wevtutil qe Security /q:"*[System[EventID=4625]]" /c:1 /f:xml`). | No real DC is reachable from the build machine. |
| 9 | 2026-11-21 | DC rules added | "User or computer account deleted" (4726/4743, Warning) and "Kerberos pre-authentication failures spike" (≥ 50 × 4771 on one DC in 5 min across all accounts, Major). "Account Operators" joins the default privileged groups. Upgrades get the new rules (the seeder adds missing built-in rules by name); an installation that saved its own privileged-group list keeps that list. | Brief WP2. The per-account (5) and per-source (20) rules already cover targeted guessing; the spike rule catches spraying that stays under both. |
| 10 | 2026-11-21 | Replication API | Replication data keeps coming from LDAP (`msDS-NCReplInboundNeighbors` over signed + sealed LDAP 389), not `System.DirectoryServices.ActiveDirectory.GetAllReplicationNeighbors`. Both return the same DS_REPL_NEIGHBOR data (partner, naming context, last success, last attempt, result, consecutive failures). | Keeps the ADSI/COM dependency out of the single-file exe and works with a least-privilege account; already pilot-ready since 1.3. |
| 11 | 2026-11-21 | Replication thresholds | "AD replication failing" now needs 1 h of continuous failure (was 15 min). New "AD replication stale": last success older than `ReplicationStaleHours` (default 3, Major); a link that was attempted but never succeeded counts as stale. | Brief WP3. Short transient failures (a DC reboot) no longer page anyone. |
| 12 | 2026-11-21 | Clock skew | Warning stays at > 30 s for 5 min; critical lowered from 240 s to 120 s. | Brief: alert at 2 min, well inside the 5-minute Kerberos limit. |
| 13 | 2026-11-21 | DC reachability | Every DC poll makes a TCP connect (3 s timeout, in parallel) to LDAP 389, Kerberos 88 and DNS 53; "DC service port unreachable" after 2 min (Major), per port. Results also stored in `DcInfo.ReachabilityJson` (migration Wp3DcHealth). The authenticated LDAP bind itself is exercised by the replication check, and its error is shown as the replication error. DNS uses TCP 53 (DC DNS servers listen on TCP too) so no DNS query library is needed. | Brief WP3, without new packages. |
| 14 | 2026-11-21 | Existing installs | Built-in rules that already exist in the database keep their stored thresholds on upgrade (the seeder only adds missing rules). Release notes tell administrators to set "AD replication failing" to 3600 s and "DC clock skew critical" to 120 s if they want the 2.0 defaults. | Never overwrite a rule an administrator may have tuned. |
| 15 | 2026-11-21 | Flap counting | A change of ifOperStatus between polls = 1 change; ifLastChange moving while the status is unchanged = 2 (down and up between polls); a reboot resets nothing. "Port flapping" (Warning) applies to all monitored ports at ≥ 4 changes in 10 min (`FlapChanges`, `FlapWindowMin`). The 24 h count is stored on the interface. | Brief WP5; ifLastChange catches bounces shorter than the poll interval. |
| 16 | 2026-11-21 | Duplex / speed | dot3StatsDuplexStatus is read every poll. Half duplex and "below expected speed" are judged on important ports only; the expected speed is set per interface (Device → Interfaces → Speed, admin). A port that comes up triggers an interface-table refresh on the next poll so a renegotiated speed is seen quickly. | Avoids thousands of alerts on access ports where half duplex or 100M is normal (phones, printers). |
| 17 | 2026-11-21 | SNMP health profiles | Vendor health can be described as data (`snmp-profiles.json` in the data folder, re-read when it changes) and replaces the vendor code for that vendor. ArubaOS-CX ships as a built-in profile with the ARUBAWIRED fan/PSU/temperature tables, marked **unverified** until checked against a pilot walk; HOST-RESOURCES-MIB and ENTITY-SENSOR-MIB remain the fallback (the generic profile for any vendor). | No ArubaOS-CX switch is reachable from the build machine; the pilot can fix OIDs without a new build. |
| 18 | 2026-11-21 | Topology | LLDP and CDP are read with the interface table (default every 30 min) on switches, routers, firewalls and "other" devices; neighbours are matched to devices by management IP, then short name/sysName; links unseen for a day are removed. Dependency suggestions walk the link graph from a device tagged `core` (else the top-level device with most links); routes never pass through servers (a server may only be suggested as parent of a VM linked to it). Suggestions are applied only by an admin, per device, and audited. | Brief WP5 ("suggest alert dependencies"), without silently changing existing parents. |
| 19 | 2026-11-21 | GPU sources | Windows: Win32_VideoController (only PCI vendors NVIDIA 10DE, AMD 1002 and Intel Arc/Flex/Data Center; BMC VGA chips such as Matrox G200/ASPEED and virtual adapters are ignored) + the "GPU Engine" / "GPU Adapter Memory" counters (utilization = busiest engine type, as Task Manager) + `nvidia-smi` through a WinRM remote shell for temperature/power/fan. Linux: `lspci` lists the GPUs and `nvidia-smi` fills the values over SSH. Physical adapter N of the counters is matched to the N-th GPU. **Pending pilot:** the WinRM shell path (needs Remote Management Users / admin rights) has only been tested with a captured ReceiveResponse. | Brief WP6; no agent, no new package. AdapterRAM is capped at 0xFFF00000 by Windows and is treated as unknown. |
| 20 | 2026-11-21 | GPU missing | GPUs are stored per server (`ServerGpus`, migration Wp6Hardware). A GPU seen before but not reported now (while the server poll succeeded) raises "GPU missing or driver error", as does a device problem code (43 = driver failure, 28 = no driver) or an nvidia-smi failure. | Survives a NetWatch restart, unlike an in-memory comparison. |
| 21 | 2026-11-21 | iLO / iDRAC | Redfish with HTTP basic authentication on every request (no session tokens to leak or expire), read-only account, every 5 min (`hardware.PollIntervalMin`). Reads ComputerSystem (+ processor/memory summaries), Chassis Thermal and Power (classic schema, supported by iLO 5/6 and iDRAC 9), Storage controllers and up to 48 drives. Certificate pinned like vCenter (CA-trusted accepted, otherwise SHA-256 trust on first use; resettable per device); revocation is never checked online. Without a Redfish credential the SNMP agent's overall health is used (HPE cpqHeMibCondition, Dell globalSystemStatus). Any present component that is Warning/Critical raises "Server hardware component not OK". **Pending pilot:** tested with HPE and Dell sample documents only. | Brief WP6. The newer ThermalSubsystem/PowerSubsystem schemas are not read yet; current iLO/iDRAC firmware still serves the classic ones. |
| 22 | 2026-11-21 | PDF library | Reports keep the built-in dependency-free PDF writer (Phase 5) instead of PDFsharp/MigraDoc. | Same result for tabular reports, nothing to license, restore or keep in the offline package cache; output verified as PDF 1.4 by tests. |
| 23 | 2026-11-21 | Report set | Seven reports: availability, alert history (with mean time to acknowledge/resolve), interface utilization (+ "most errors"), server capacity (CPU/memory average, peak and trend; disks and datastores with growth and "predicted to fill within 30 days"), DC security (+ off-hours admin logons, log cleared / audit policy), device inventory, and the new VMware report (hosts, datastore capacity, snapshots oldest first, powered-off VMs). "Days until full" assumes the period's growth continues linearly. Preview renders the same document on screen (tables capped at 200 rows). | Brief WP7. |
| 24 | 2026-11-21 | Backup method | Backups keep `VACUUM INTO` per database (Phase 5) instead of the SQLite online-backup API. | Both give a transactionally consistent copy while NetWatch keeps writing; `VACUUM INTO` also compacts it and needs no page-by-page loop. |
| 25 | 2026-11-21 | Portable credentials | "Back up for another server" adds `credentials.portable.json`: each secret AES-256-GCM encrypted with a key from PBKDF2-SHA256 (600,000 iterations, random salt) over an admin password (≥ 12 characters, never stored), plus a check value so a restore verifies the password before changing anything. Restoring with the password re-protects every secret with the new server's DPAPI. | DPAPI blobs only decrypt on the machine that made them. |
| 26 | 2026-11-21 | Restore from the console | The console validates the backup (manifest, checksums, password), writes `restore-pending.json` (password DPAPI-protected) and stops NetWatch with exit code 75; the installer now sets `sc failureflag NetWatch 1`, so the service manager restarts it. The next start restores **before any database is opened**, deletes the marker first (never loops) and writes a `BackupRestored` / `RestoreFailed` audit entry into the restored database. Default schedule changed to daily 02:00 (keep 14). **Pending pilot:** automatic restart verified only in console mode; as an installed service in WP12. | Restoring while SQLite files are open is unsafe; restoring at start-up is the same code path as `--restore`. |
| 27 | 2026-11-21 | NOC kiosk | Wall screens sign in with a revocable display link (Settings → Users → NOC wall displays) instead of a shared password: the link token (256-bit, only its SHA-256 stored, shown once) signs the browser in as a hidden kiosk account (AuthSource Kiosk, role Viewer, no password, not listed under Users) with a persistent cookie and no idle timeout; revoking disables the account and its sessions at once. The NOC view hides "leave NOC" for kiosks. | Brief WP9 ("no login timeout, dedicated read-only role or kiosk token") without weakening the idle timeout of people's sessions. |
| 28 | 2026-11-21 | NOC layout | Font sizes scale with the viewport (`clamp(14px, 0.85vw, 34px)`) so the same page reads at 1080p and 4K; per-group tiles (green/amber/red, pulsing when something is down), the open critical/major alerts list, rotating panels (problems, sites, busiest links, DCs) and a scrolling DC security ticker (Warning and above, last 24 h). Sound for new critical/major alerts uses the existing live alert sounds; the NOC header has its own sound button because browsers need one click before playing audio. | Brief WP9. |
| 29 | 2026-11-21 | Pilot tools | Settings → Pilot tools (admin): one connection test per check — ping, SNMP v2c/v3 (system group + ifDescr walk), WinRM/WMI (+ GPU query), remote Security log read of 1 event, SSH, vCenter login + inventory, iLO/iDRAC Redfish, LDAP/LDAPS bind (account typed in, never stored) with group→role mapping, SMTP test mail, and "syslog/traps received from this source in the last N minutes". Each step shows the exact error plus a hint (ports, ACLs, groups). Tests never pin certificates. The last 100 results stay in memory for the bundle. Simulated devices are not SNMP/WinRM agents, so tests against them fail by design; the simulator exercises the collectors, the tests exercise the real network. | Brief WP10. |
| 30 | 2026-11-21 | Diagnostic bundle | One zip: logs of the last 24 h (≤ 60 MB), connection-test history, poll statistics, database settings and appsettings.json with every property whose name contains password/secret/community/token/passphrase/key-like words replaced, credential names/kinds/hints only, the inventory without secrets, and SNMP walks (≤ 20 devices, 15 subtrees incl. ENTITY-MIB, ENTITY-SENSOR, HOST-RESOURCES, LLDP, Cisco/HP/ArubaOS-CX/Juniper/HPE/Dell health) in `snmpwalk -On` format — the same format the parser tests read, so a pilot walk can become a test sample directly. Discovery already works as a dry run (scan → review → add selected). | Brief WP10. |
